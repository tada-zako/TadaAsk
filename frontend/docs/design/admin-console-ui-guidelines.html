Global UI direction

TadaAsk Admin Console 是一个深色、克制、中密度的开发者控制台。

本规范用于指导 Admin Console 的全局 UI 设计与可复用组件实现。它不定义单个页面的业务流程， 不替代后端 API 文档，也不约束 Visitor Widget 的视觉系统。

视觉气质

黑白为主、冷青强调、少量语义色。整体接近常规 dev console， 信息密度低于 Vercel，但保留后台操作效率。

MVP 优先级

优先让 Project、Sources、Chat、Settings 形成清晰操作路径。 Analytics 保留骨架，不用假数据制造完成感。

实现方式

使用 Vue 3、Tailwind v4、shadcn-vue、lucide 图标。基础组件来自 shadcn-vue， 业务组合组件放在 console 层封装。

全局布局

所有 Admin 页面共享同一 AppShell。页面内容只替换主内容区，避免每页重复定义框架。

AppShell / Sidebar / Topbar
Sidebar 桌面宽度建议 260px 到 280px；包含品牌、ProjectSwitcher、分组导航。导航 active 使用冷青弱底和冷青边框。
Topbar 高度约 64px，sticky。用于 breadcrumb、全局搜索、少量高频动作。避免塞入页面级复杂配置。
Content 主内容最大宽度约 1320px 到 1360px，页面 padding 桌面 28px 到 30px，section 间距约 22px 到 28px。
Responsive 中等宽度可折叠 sidebar 文本，仅保留图标。移动端 MVP 不优先优化复杂表格，可横向滚动。

字体与文本

控制台不使用夸张 hero 字体。标题清楚，正文克制，表格文字保持扫描效率。

Font stack Aptos, Segoe UI, ui-sans-serif, system-ui。实际实现可以沿用 shadcn-vue 默认字体配置，但避免引入额外远程字体。
Page title 26px 到 38px，字重 700 左右。仅页面主标题使用较大字号。
Panel title 14px 到 18px，字重 650 到 700。不要在 card 内使用 hero 级标题。
Table text 表头 11px uppercase，单元格 13px。重要对象名使用主文本色，其余字段使用 muted。

间距、圆角与边框

深色控制台依赖边框和层级，不依赖重阴影。圆角保持 6px 到 8px 的工具感。

Radius

小控件 6px，panel 和 table shell 8px，dialog 可到 10px。避免大圆角卡片感。

Border

常规边框 #24262b，内部弱分隔 #1a1c20，focus 使用冷青透明 ring。

Density

按钮高度 36px，输入 38px，表格行高约 50px 到 58px，状态行约 64px。

按钮、输入与选择器

按钮和表单优先基于 shadcn-vue 扩展。主动作使用冷青，次动作使用深色 surface。

反馈、弹层与空状态

反馈组件必须说明下一步动作。Dialog 用于确认或创建，Sheet 用于复杂配置。

Informational callout 用于说明 MVP 限制、配置提示或需要人工 review 的轻量信息。
Warning callout 用于 pending、draft、reserved、未完成配置等非失败状态。
Destructive callout 用于删除、失效 API key、不可恢复操作前的确认说明。

Console 组合组件

这些组件不是业务逻辑本身，而是跨页面重复出现的 UI 结构。

ProjectSwitcher

放在 sidebar 顶部，用于切换当前工作上下文。显示首字母、项目名和当前状态即可。

PageHeader

包含页面标题、短说明、主要动作。避免每个页面自行拼出不同标题布局。

DataTableShell

组合 toolbar、filter、table、pagination、empty state，用于 Sources 和 API Keys。

SettingsPanel

用于 Global / Project settings。左侧或顶部 tabs 分组，右侧显示表单区域。

ChatMessageBubble

Admin 和 assistant 区分背景。Admin chat 可配右侧 CitationPanel。

CitationCard

显示 source item、score、chunk 摘要。Admin 侧可比 visitor 侧展示更多检索细节。

shadcn-vue 使用约定

项目已配置 shadcn-vue、new-york、neutral base、lucide。规范应映射到 CSS variables，而不是手写另一套 UI 库。

shadcn token / component TadaAsk 规范 建议
--background #050505 页面背景和 body 基底。
--card #101113 / rgba panel panel、card、table shell 统一使用该层级。
--primary #24d3c4 只用于主按钮、focus、active nav 和少量图表重点。
Button primary / secondary / ghost / destructive / icon 基于 shadcn-vue Button variant 扩展，不重复造基础按钮。
Input / Select / Textarea 深色 surface、细边框、冷青 focus ring 表单项通过 Field wrapper 统一 label、help、error。
Dialog / Sheet / Popover 深色浮层，边框区分层级 Dialog 处理短流程，Sheet 处理复杂配置。
Table 中密度行高，弱 hover，表头 uppercase 封装 DataTableShell，避免每页重复 filter 和 empty state。
Badge Pill / Status label 状态必须配文字，不只依赖颜色。
组件分层建议 components/ui 保留 shadcn-vue 原子组件； components/console 放 AppShell、ProjectSwitcher、DataTableShell、CitationPanel 等组合组件。

动效

Admin Console 的动效应该服务于状态感，不追求展示感。

Hover 按钮、导航、表格行可以轻微改变背景色。不要使用大位移和弹跳。
Focus 表单和可交互元素使用冷青 focus ring。键盘操作必须可见。
Loading Skeleton 使用 1.4s 到 1.8s 的呼吸动效。长任务进度使用 progress 和 stage 文案。
Dialog / Popover 可使用短淡入和轻微 scale，但时长应控制在 120ms 到 180ms。

可访问性

深色 UI 必须控制对比度。图标按钮、状态色和弹层都需要基本可访问性。

必须做到

  • Icon button 必须有 aria-label，复杂图标加 tooltip。
  • 状态不能只靠颜色表达，需要文字或图标。
  • Dialog 打开后焦点进入弹层，关闭后返回触发按钮。
  • 表单 label、help、error 应通过 Field wrapper 管理。

避免

  • 大面积纯黑上使用过暗灰字。
  • 把 tooltip 当正文说明使用。
  • loading 时填假数据。
  • 在同一页面混用不同圆角、按钮高度和表格密度。

本规范不覆盖的内容

为了保持 MVP 灵活性，以下内容后续按页面或模块单独分析。

不包含 单个页面的业务流程、API 字段、后端状态机、数据 mock 组织方式。
不包含 Visitor Widget 的完整 UI 规范、Widget public API、Widget CSS token 列表。
不包含 Analytics 真实指标模型、RAG 高级配置的业务边界、Project 创建流程细节。

Do

  • 优先使用现有 token 和 shadcn-vue 组件。
  • 让页面结构稳定，业务内容按 section 填入。
  • 用冷青表达当前上下文和关键操作。
  • 为 empty、loading、error 都准备可复用状态。

Do not

  • 不要引入紫色渐变、营销 hero 或装饰型背景图。
  • 不要把 analytics 假装成已经完成。
  • 不要为每个页面手写不同 table、toolbar、dialog。
  • 不要把业务规则写进全局 UI 规范。
